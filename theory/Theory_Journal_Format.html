Matching Engine Journal & Replay · Knowledge notes

Format { On-disk records }

How commands become durable bytes. Same spirit as MDS wire framing — packed structs, explicit byte order, a discriminator — but the consumer is a file reader, not recv.

01

Why binary on disk

  • Deterministic size — fixed offsets; easy CRC over a known span.
  • Fast append / scan — no tokenization; replay is a tight loop.
  • Integrity — truncate/corrupt tests need a precise “where the record ends.”
  • CV signal — shows you can design a storage format, not only a socket protocol.
vs MDS

MDS: fixed-size messages on a TCP stream (partial reads). Journal: complete records appended to a file (partial tail after crash). Framing discipline transfers; failure modes differ.

02

File header (once per journal)

Write a short header at create time so a random file is not mistaken for a journal, and so format changes are detectable.

proposed file header (host → little-endian on disk)
offset  size  field
0       4     magic      = 'M','E','J','R'   // Matching Engine Journal Replay
4       2     version    = 1
6       2     flags      = 0                // reserved (e.g. fsync policy note)
8       8     created_ns = steady or wall   // optional; wall ok for metadata only
────────────────────────────────────────────
total  16 bytes, packed

Do not put match decisions in the header. Metadata only. Replay ignores created_ns for book state.

03

Record framing

SchemeIdeav1 lean
Fixed-size by type Read type, then known remainder Good if NEW and CANCEL sizes are fixed
Length-prefixed uint32 len + payload + CRC More flexible; slightly more states

Recommended v1: type byte + fixed body per type + CRC32 trailer. Both command kinds are small and fixed — no strings. Reader algorithm:

  1. Need at least 1 byte of type.
  2. Map type → expected body size N.
  3. Need 1 + N + 4 bytes total; if EOF mid-record → truncated tail (fail).
  4. Verify CRC over type ‖ body; mismatch → corrupt.
record sketch
[ type:u8 ][ body: fixed by type ][ crc32:u32 ]

type 1 = NEW
type 2 = CANCEL
// unknown type → fail closed (do not skip)
04

Command bodies

Mirror the LOB request fields you already use in scenarios — enough to call submit / cancel without re-parsing text.

TypeBody fields (suggested)Notes
NEW order_id:u64, side:u8, otype:u8, qty:i64, price:i64 Qty/price match LOB int64_t ticks
CANCEL order_id:u64 Idempotent cancel semantics live in the LOB
journal_record.hpp
enum class CmdType : uint8_t { New = 1, Cancel = 2 };

#pragma pack(push, 1)
struct NewBody {
  uint64_t order_id;
  uint8_t  side;      // 0 buy / 1 sell — map to lob::Side
  uint8_t  otype;     // limit / market
  int64_t  qty;
  int64_t  price;     // ticks
};
struct CancelBody {
  uint64_t order_id;
};
#pragma pack(pop)

// Disk record = type + body + crc32(type||body)
static_assert(sizeof(NewBody) == 26, "…");
static_assert(sizeof(CancelBody) == 8, "…");
Single-symbol v1

Omit symbol_id until you need multi-book journals. Gateway sharding is a different problem; this repo is one engine, one log.

05

Packing / alignment

Compilers insert padding between members. On disk that makes sizeof compiler-dependent — bad for goldens and CRC spans.

  • Use #pragma pack(push, 1) … pack(pop) around on-disk structs.
  • static_assert exact sizes in the header (MDS pattern).
  • Prefer encode field-by-field into a byte buffer over fwrite(&host_struct) if you ever need cross-endian files.
06

Endianness on disk

Network byte order is big-endian. For a local journal that only ever runs on one machine, little-endian fixed layout is fine and matches Apple Silicon / x86 hosts.

ChoiceWhen
LE fixed (recommended v1) Single-host learning project; document “LE on disk”
BE / network order If you want identical habits to MDS hton*
Decision lean

Little-endian packed + document it in the header comment and README. Optional later: a flag bit for BE. Never leave endianness implicit in interviews — say which you picked and why.

07

Encode / decode API shape

mental API
// Host-side command (not packed):
struct Command { CmdType type; /* union or variant fields */ };

// Serialize into bytes ready for append (includes CRC):
std::vector<uint8_t> encode(const Command& c);

// Parse one record from a buffer; returns bytes consumed or error:
enum class ReadStatus { Ok, Truncated, BadChecksum, BadType, Done };
ReadStatus decode_one(const uint8_t* p, size_t n,
                      Command& out, size_t& consumed);

Keep LOB types out of the on-disk structs if possible — map side/otype bytes to lob::Side / OrderType at the boundary. That keeps the journal format independent of LOB header churn.

08

Versioning habit

  • Bump version in the file header when the record layout changes.
  • Readers that see an unknown version must refuse to replay (fail closed).
  • Do not silently reinterpret old bytes under a new layout.
09

Project decision

Decision

16-byte file header (magic MEJR, version 1) + type-discriminated fixed bodies for NEW/CANCEL + CRC32 trailer over type‖body. Little-endian packed. Rejected: JSON lines, length-prefixed variable blobs in v1, embedding full LOB event streams.
